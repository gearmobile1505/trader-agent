1. **Daily-loss gate must count realized + unrealized P&L** (`compute_daily_pnl()`, ~line 704). It currently sums only `unrealizedPl` from cached open positions — the docstring claims realized + unrealized, but the realized part is an unimplemented comment — and it returns 0.0 on exception, so the gate fails open and a day of already-closed losers reads ~$0. Evidence 2026-09-30: the bot closed four losers totaling −$430.58 net (XAUUSD.R stopped 02:53 ET −$106.45 and 03:08 ET −$106.90; UKOIL.R whipsaw stopped 03:16 ET −$116.48 and 03:44 ET −$100.75) and the −$400 cap never fired. Sum realized P&L for the current America/New_York calendar day (positions closed since 00:00 ET) from TradeLocker history, plus current unrealized P&L of open positions. Reject new entries at total ≤ −$400. Keep the gate deterministic and before the AI call. If realized history cannot be fetched, fail CLOSED (reject the entry) and log a loud `[DAILY P&L]` error — never silently return 0. Log realized, unrealized, and total whenever the gate is evaluated (at minimum on rejection).

2. **Persist the post-stop-out cooldown across restarts.** `_STOP_OUT_COOLDOWN` is an in-memory dict, so a restart silently clears active 60-minute cooldowns (demonstrated 2026-10-01: the server restart wiped it; harmless only because the book was flat). Serialize expiries to a small JSON state file alongside the bot's other state, load at startup, prune expired entries on load and on check. Keep the 60-minute per-symbol duration unchanged.

3. **XPDUSD.R slippage guard must fail closed on unverifiable data** (`validate_slippage_guard()`, ~line 800). It currently returns True ("Spread data unavailable" / "Slippage check skipped") when quote/spread data is unavailable or the check errors. For XPDUSD.R only: if the current spread cannot be fetched or the check errors, reject the entry under the `slippage_guard` gate with a clear log line. Keep the existing limits unchanged: block when spread > 0.5% of price; warn at 2x stop-distance fill.

4. **Session-map telemetry (no behavior change).** At startup, log the effective session map — every symbol in TOP_SYMBOLS with its enabled sessions and the ET windows from SESSIONS_ET. In the existing outside-session rejection, include the symbol's allowed sessions in the human-readable log line (the JSON alert log already carries `allowed_sessions`; the readable string does not).

5. **NEW — test the handler, not just the helpers.** All 16 tests in `scripts/test_replay_gates.py` exercise gate helper functions in isolation and were green while `process_tradingview_alert()` itself crashed on 6 of 9 live alerts (the bot placed zero trades for ~19 h, 2026-09-30 ~10:00 ET → 2026-10-01 ~05:08 ET). These tests must fail against the pre-`cdfcb56` gate ordering.

Ensure any unexpected exception inside `process_tradingview_alert()` is recorded via `log_alert` with status `"error"` and the exception text before the error propagates. No behavior change on any non-crashing path.
